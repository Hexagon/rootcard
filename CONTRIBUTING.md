# Contributing to rootcard

Thank you for helping. rootcard is security software, so changes are held to a few strict rules. They are short, and
the same for people and for coding agents ([AGENTS.md](AGENTS.md) is the complete list).

Everyone taking part follows the [code of conduct](CODE_OF_CONDUCT.md).

## Security problems

Never in a public issue or pull request. Report them privately as [SECURITY.md](SECURITY.md) describes.

## Before you start

- **Questions, ideas and bugs:** open an issue. For anything larger than a fix, describe it in an issue first, so we can
  agree on the design before you write the code.
- **Read the spec.** [spec/SPEC.md](spec/SPEC.md) is the source of truth for every format, label and rule;
  [docs/CONCEPTS.md](docs/CONCEPTS.md) explains it. Code follows the spec, never the other way round.
- **What is planned** is in [docs/PLAN.md](docs/PLAN.md). Open items there are good places to help.

## The rules that matter most

1. **Rust and JavaScript agree byte for byte.** `crates/rootcard` and `packages/rootcard` implement the same functions.
   A change to one is a change to the other, in the same pull request, with vectors in `spec/vectors/` (generated by
   `cargo run -p xtask -- vectors --update`).
2. **Anything hashed or signed is a format change.** It needs a new `v` or label, keeps reading the old version
   forever, and says so in the commit message (SPEC §22).
3. **No home-made cryptography** and no new dependency without a reason in the pull request. The npm package has no
   dependencies at all, not even for tests.
4. **The cores are pure:** no I/O, no clock, no randomness of their own; time and random bytes are passed in.
5. **Every rule has a test** that shows it is enforced, with an accept and a reject case. A new parser or verifier gets
   a fuzz target ([fuzz/README.md](fuzz/README.md)).
6. **Documentation is part of the change.** Update the changelog (`## Unreleased`) of every package you change, and
   every document that describes what you changed (the table in [AGENTS.md](AGENTS.md) rule 9).
7. Code, comments, docs and commit messages are in **English**. Nothing application-specific belongs here.

## Checks

Run these before you push; CI runs them too.

```bash
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo run -p xtask -- vectors --check
cargo run -p xtask -- repo-check
(cd packages/rootcard && npm test)          # Node >= 20
```

The browser tests (`tests/browser`) and the fuzzers (`fuzz/`) run in CI; how to run them locally is in
[AGENTS.md](AGENTS.md).

## Pull requests

Small and focused, one change per pull request, with a description of what changed and why, and the rule ids it touches
(`[LOG-12]`). Releases are prepared as described in [docs/RELEASING.md](docs/RELEASING.md) and published only by the
owner, through CI.
